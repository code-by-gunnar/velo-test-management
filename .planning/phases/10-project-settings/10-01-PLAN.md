# Plan 10-01: Project Settings (Rename + Delete)

## Goal
Add editable project name and delete-project functionality to the existing project settings General tab. Users can rename their project inline and delete projects they no longer need, with a calm two-step confirmation and a last-project guard.

## Requirements Covered
- **PST-01**: Project settings General tab shows an editable project name field (calls PATCH endpoint)
- **PST-02**: Project settings General tab has a "Delete project" section with calm confirmation
- **PST-03**: Deletion is blocked with a message when the project is the last one in the workspace

## Success Criteria (from ROADMAP)
1. Project settings General tab shows the project name in an editable field — on save, calls `PATCH /api/workspaces/:id/projects/:projectId` with `{ name }`
2. Below the name field, a "Delete project" section with calm gray confirmation (matching Clean Elevation pattern)
3. Delete calls `DELETE /api/workspaces/:id/projects/:projectId` — on 204, navigates to workspace root (which redirects to remaining project)
4. If the project is the last one in the workspace, the delete button is disabled with text explaining "You need at least one project" — verified by checking project count from the list endpoint
5. Project key and IDs remain displayed as read-only (existing behavior preserved)

## Files to Modify

| File | Action | Purpose |

## Implementation

### Task 1: Add SSR data — fetch project name and project count

**Modify:** `getServerSideProps` in `settings.tsx`

The SSR already fetches the project by key to get `projectId`. Extend it to also capture `projectName` from the same response, and fetch the project list to get a count.

**Changes to `getServerSideProps`:**

```typescript
let projectId = ""
let projectName = ""
let projectCount = 0

if (workspaceId && token) {
  try {
    // Fetch current project (already exists — extend to capture name)
    const res = await fetch(
      `${apiUrl}/api/workspaces/${workspaceId}/projects/by-key/${projectKey}`,
      { headers: { authorization: `Bearer ${token}` } }
    )
    if (res.ok) {
      const project = await res.json() as { id: string; name: string }
      projectId = project.id
      projectName = project.name
    }

    // Fetch project count for last-project guard
    const listRes = await fetch(
      `${apiUrl}/api/workspaces/${workspaceId}/projects`,
      { headers: { authorization: `Bearer ${token}` } }
    )
    if (listRes.ok) {
      const projects = await listRes.json() as Array<{ id: string }>
      projectCount = projects.length
    }
  } catch {
    // projectId stays empty
  }
}

return {
  props: { slug, projectKey, workspaceId, projectId, projectName, projectCount },
}
```

### Task 3: Add editable project name section to General tab

Replace the current General tab content with a two-card layout:

**Card 1 — Project name (editable) + read-only IDs:**

State and handlers in the component:

```typescript
const router = useRouter()
const [name, setName] = useState(projectName)
const [saving, setSaving] = useState(false)
const [saveError, setSaveError] = useState("")
const [saveSuccess, setSaveSuccess] = useState(false)

const nameChanged = name.trim() !== projectName && name.trim().length > 0

async function handleSaveName() {
  setSaving(true)
  setSaveError("")
  setSaveSuccess(false)
  try {
    const res = await fetch(
      `/api/backend/workspaces/${workspaceId}/projects/${projectId}`,
      {
        method: "PATCH",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ name: name.trim() }),
      }
    )
    if (!res.ok) {
      const data = await res.json()
      throw new Error(data.error ?? "Failed to save")
    }
    setSaveSuccess(true)
    // Brief success flash, then clear
    setTimeout(() => setSaveSuccess(false), 2000)
  } catch (err) {
    setSaveError(err instanceof Error ? err.message : "Failed to save")
  } finally {
    setSaving(false)
  }
}
```

### Task 4: Add `ProjectDeleteSection` private component

Add a private component at the bottom of `settings.tsx` (same pattern as `ProjectSwitcher` in sidebar.tsx).

**Follow the DeletionPanel pattern** from `apps/web/src/components/settings/DeletionPanel.tsx` — calm gray icon, factual text, two-step confirmation.

```typescript
function ProjectDeleteSection({
  workspaceId,
  projectId,
  slug,
  projectCount,
}: {
  workspaceId: string
  projectId: string
  slug: string
  projectCount: number
}) {
  const router = useRouter()
  const [confirming, setConfirming] = useState(false)
  const [deleting, setDeleting] = useState(false)
  const [error, setError] = useState("")

  const isLastProject = projectCount <= 1

  async function handleDelete() {
    setDeleting(true)
    setError("")
    try {
      const res = await fetch(
        `/api/backend/workspaces/${workspaceId}/projects/${projectId}`,
        { method: "DELETE" }
      )
      if (res.status === 204) {
        // Navigate to workspace root — it auto-redirects to remaining project
        void router.push(`/app/${slug}`)
        return
      }
      const data = await res.json()
      throw new Error(data.error ?? "Failed to delete project")
    } catch (err) {
      setError(err instanceof Error ? err.message : "Failed to delete project")
      setDeleting(false)
    }
  }

  return (
    <div className="rounded-lg border border-gray-200 bg-white p-5">
      <div className="flex items-start gap-3">
        <Trash2 className="mt-0.5 h-4 w-4 shrink-0 text-gray-400" />
        <div className="flex-1">
          <h3 className="text-sm font-semibold text-gray-900">
            Delete this project
          </h3>
          <p className="mt-1 text-sm text-gray-500">
            Permanently removes this project and all its test cases, suites, and run history.
          </p>

          {error && (
            <p className="mt-3 text-sm text-fail">{error}</p>
          )}

          {isLastProject ? (
            <p className="mt-3 text-sm text-gray-500">
              You need at least one project in your workspace. Create another project before deleting this one.
            </p>
          ) : confirming ? (
            <div className="mt-4">
              <p className="mb-3 text-sm text-gray-600">
                Are you sure? This cannot be undone.
              </p>
              <div className="flex items-center gap-2">
                <Button
                  variant="destructive"
                  size="sm"
                  onClick={() => void handleDelete()}
                  disabled={deleting}
                >
                  {deleting ? "Deleting..." : "Confirm delete"}
                </Button>
                <Button
                  variant="secondary"
                  size="sm"
                  onClick={() => setConfirming(false)}
                  disabled={deleting}
                >
                  Cancel
                </Button>
              </div>
            </div>
          ) : (
            <div className="mt-4">
              <Button
                variant="destructive"
                size="sm"
                onClick={() => setConfirming(true)}
              >
                <Trash2 className="mr-1.5 h-3.5 w-3.5" />
                Delete project
              </Button>
            </div>
          )}
        </div>
      </div>
    </div>
  )
}
```

- `border-gray-200` — card borders
- `border-gray-100` — internal dividers
- `text-gray-900` — headings
- `text-gray-500` — labels, secondary text
- `text-gray-400` — Trash2 icon (calm, muted)
- `text-gray-600` — confirmation text
- `text-fail` — error messages
- `text-pass` — save success flash
- `bg-gray-100` — code badge backgrounds
- `rounded-lg` — card containers
- Button `primary` — save name
- Button `destructive` — delete (uses `fail-*` tokens from cva)
- Button `secondary` — cancel
- `FormField` + `Input` — name editing
- `max-w-sm` — input width constraint

## Edge Cases
1. **Empty name:** Save button disabled when `name.trim()` is empty or unchanged from original
2. **Name unchanged:** Save button disabled — no unnecessary PATCH calls
3. **Network failure on save:** try/catch shows error message below input
4. **Network failure on delete:** try/catch shows error, re-enables buttons
5. **Last project:** Delete button replaced with disabled message — client-side check via `projectCount`
6. **Delete then navigate:** `router.push` fires immediately on 204 — no stale state
7. **Double-click delete:** `disabled={deleting}` prevents multiple DELETE calls
8. **SSR project count stale:** If user opens a second tab and deletes a project, count could be stale. This is acceptable — the API would still succeed/fail correctly. The guard is a UX convenience, not a security measure.

## What This Plan Does NOT Cover
- Editing project key (explicitly out of scope per REQUIREMENTS.md)
- Project description field (out of scope for v1.3)
- Backend last-project guard (the DELETE endpoint has no server-side check — client handles it via project count; a backend guard could be added later)
