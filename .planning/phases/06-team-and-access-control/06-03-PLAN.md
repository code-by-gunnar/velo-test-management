Extend the session plugin's preHandler hook to check the Valkey deactivation blocklist after decoding the JWT. This ensures deactivated users are rejected on their next request without waiting for JWT expiry.

After the existing block that sets `request.userId`, `request.workspaceId`, `request.userRole` from the JWT payload, add:

```typescript
// Check deactivation blocklist (USR-04: immediate session invalidation)
if (id && request.workspaceId) {
  try {
    const isBlocked = await fastify.valkey?.get(`deactivated:${request.workspaceId}:${id}`)
    if (isBlocked) {
      // Clear session context — requireAuth will return 401
      request.userId = ""
      request.workspaceId = null
      request.userRole = null
      return
    }
  } catch {
    // Fail open: if Valkey is down, allow the request through
    // The membership check in individual routes is the secondary guard
  }
}
```

Import or access Valkey:
- The session plugin currently does NOT import Valkey. To access it, use `fastify.valkey` if it's decorated on the Fastify instance, OR import `valkey` from `../../lib/valkey.js` directly.
- Check how other plugins access Valkey in this codebase and use the same pattern. If `valkey` is imported directly (not decorated), use `import { valkey } from "../lib/valkey.js"` and call `valkey.get(...)`.

The blocklist check is fail-open (empty catch block) because:
1. If Valkey is down, individual route handlers still check membership via DB
2. A preHandler failure should not block all authenticated requests
