  <action>
Present the following verification checklist to the user. Start the dev environment (`pnpm dev` in both apps/api and apps/web) before presenting.

**USR-01 — Invite by email:**
1. Go to Settings > Team tab as an admin
2. Enter an email address, select a role (e.g., Editor), click "Send Invite"
3. Verify: 201 success, invite appears in the "Pending Invitations" section

**USR-02 — Invitation email:**
1. Check the BullMQ email queue (or Resend dashboard if RESEND_API_KEY is configured)
2. Verify: A "workspace-invite" job was queued with correct inviteUrl, workspaceName, inviterName
3. If Resend is configured: verify the email arrives with a clickable accept link

**USR-03 — Role change:**
1. In Settings > Team, change a member's role from Editor to Viewer using the dropdown
2. Verify: Role updates immediately in the UI
3. Verify: That member's next API request uses the new role (check Valkey role cache was busted)

**USR-04 — Deactivation:**
1. In Settings > Team, click "Deactivate" on a non-admin member
2. Confirm the confirmation prompt
3. Verify: Member disappears from the active list (or shows as inactive)
4. Verify: If that user tries to access any workspace resource, they get 401

**USR-05 — Editor seat cap:**
1. On a Free tier workspace, invite editors until you reach 3 active editors
2. Try to invite a 4th editor
3. Verify: 403 response with TIER_LIMIT_EXCEEDED error and upgrade prompt
4. Verify: Viewer invitations still work (unlimited)

**USR-06 — Tier limits:**
1. Verify the error message from USR-05 includes clear upgrade language
2. Try to change a viewer's role to editor when the cap is reached
3. Verify: 403 TIER_LIMIT_EXCEEDED on role upgrade too

**Accept invite flow:**
1. Open the invite URL from USR-02 in a browser (logged in as the invited user or a new user)
2. Verify: User is added to the workspace and redirected to the workspace dashboard
3. Verify: If not logged in, user is redirected to login with ?next= pointing back to accept-invite
