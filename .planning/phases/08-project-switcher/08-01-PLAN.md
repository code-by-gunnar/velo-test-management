# Plan 08-01: Project Switcher Dropdown

## Goal
Replace the static workspace pill in the sidebar with a clickable project switcher dropdown. Users see all projects, the current project is highlighted, clicking switches projects, and editors/admins see a "+ New project" action.

## Requirements Covered
- **PSW-01**: Clicking workspace pill opens dropdown listing all projects
- **PSW-02**: Current project visually highlighted
- **PSW-03**: Clicking a project navigates to its test cases page
- **PSW-04**: "+ New project" action for editors/admins

## Success Criteria (from ROADMAP)
1. Clicking workspace pill opens dropdown listing projects from `GET /api/workspaces/:id/projects`
2. Current project (matching URL `projectKey`) highlighted with `bg-primary-selected text-primary`
3. Clicking different project navigates to `/app/{slug}/{projectKey}/cases` and updates `velo:last-project-key`
4. "+ New project" row at bottom for editors/admins (hidden for viewers)
5. Dropdown closes on outside click and Escape key
6. When sidebar collapsed, pill still clickable and dropdown positioned correctly

## Files to Modify

| File | Action | Purpose |
|------|--------|---------|
| `apps/web/src/components/layout/sidebar.tsx` | Modify | Add ProjectSwitcher component, replace static pill |

**No new files needed.** The ProjectSwitcher is a private component in sidebar.tsx (same pattern as UserMenu).

## Implementation

### Task 1: Add ProjectSwitcher component to sidebar.tsx

Add a new `ProjectSwitcher` private component after the `UserMenu` component (bottom of file). Following the exact same pattern as `UserMenu` (lines 286-380):

**Props:**
```typescript
function ProjectSwitcher({
  slug,
  collapsed,
  effectiveProjectKey,
  canEdit,
  workspaceId,
}: {
  slug: string
  collapsed: boolean
  effectiveProjectKey: string | undefined
  canEdit: boolean
  workspaceId: string
})
```

**State:**
```typescript
const [open, setOpen] = useState(false)
const [projects, setProjects] = useState<Array<{ id: string; name: string; project_key: string }>>([])
const menuRef = useRef<HTMLDivElement>(null)
const router = useRouter()
```

**Data fetching:**
- `useEffect` that fetches `/api/backend/workspaces/${workspaceId}/projects` on mount
- Sets `projects` state with the response array
- Matches the existing avatar fetch pattern in UserMenu (lines 305-312)
- Only fetch when `workspaceId` is truthy

**Click-outside handler:**
- Identical to UserMenu pattern (lines 314-323): `mousedown` listener on document, check `menuRef.current.contains()`

**Escape key handler (new — not in UserMenu):**
```typescript
useEffect(() => {
  if (!open) return
  function handleKeyDown(e: KeyboardEvent) {
    if (e.key === "Escape") setOpen(false)
  }
  document.addEventListener("keydown", handleKeyDown)
  return () => document.removeEventListener("keydown", handleKeyDown)
}, [open])
```

**Render structure:**

```
<div className="relative px-3 py-3" ref={menuRef}>
  {/* Dropdown (conditional) */}
  {open && (
    <div className="absolute left-2 right-2 top-full mt-1 z-50 rounded-lg border border-gray-200 bg-white py-1 shadow-dropdown">
      {/* Project list */}
      {projects.map(project => (
        <button
          key={project.id}
          onClick={() => { navigate to project; close dropdown }}
          className={clsx(
            "flex w-full items-center gap-2 px-3 py-2 text-sm transition-colors",
            project.project_key === effectiveProjectKey
              ? "bg-primary-selected text-primary font-medium"
              : "text-gray-700 hover:bg-gray-50"
          )}
        >
          <div className="h-5 w-5 rounded-sm bg-gray-200 flex items-center justify-center text-[9px] font-semibold text-gray-600">
            {project.name.slice(0, 2).toUpperCase()}
          </div>
          <span className="flex-1 truncate text-left">{project.name}</span>
          {/* Check icon for current project */}
        </button>
      ))}

      {/* Divider + New project (editors/admins only) */}
      {canEdit && (
        <>
          <div className="mx-2 my-1 border-t border-gray-100" />
          <button
            onClick={() => { /* Phase 2 will wire this */ setOpen(false) }}
            className="flex w-full items-center gap-2 px-3 py-2 text-sm text-gray-500 hover:bg-gray-50 transition-colors"
          >
            <Plus size={14} className="text-gray-400" />
            New project
          </button>
        </>
      )}
    </div>
  )}

  {/* Trigger — the workspace pill (clickable) */}
  <button
    type="button"
    onClick={() => setOpen(v => !v)}
    className="flex w-full items-center gap-2 rounded-lg bg-gray-100 px-3 py-2"
  >
    <div className="flex h-6 w-6 shrink-0 items-center justify-center rounded-sm bg-primary text-[10px] font-semibold text-white">
      {slug.slice(0, 2).toUpperCase()}
    </div>
    {!collapsed && (
      <>
        <span className="flex-1 truncate text-left text-sm font-semibold text-gray-800">
          {currentProjectName || slug}
        </span>
        <ChevronDown
          size={14}
          className={clsx("shrink-0 text-gray-500 transition-transform", open && "rotate-180")}
        />
      </>
    )}
  </button>
</div>
```

**Key behaviors:**
- **Navigation on click:** `router.push(\`/app/${slug}/${project.project_key}/cases\`)` then `setOpen(false)`
- **localStorage update:** `localStorage.setItem("velo:last-project-key", project.project_key)` + dispatch StorageEvent for `useSyncExternalStore` sync
- **Current project name:** Derive from `projects.find(p => p.project_key === effectiveProjectKey)?.name`
- **"+ New project" button:** Placeholder `onClick` for now — Phase 2 will add the create modal. For now, just navigate to a future route or show a toast.

## Design Tokens Used
- `bg-primary-selected` / `text-primary` — current project highlight
- `bg-gray-100` — pill background
- `bg-gray-50` / `hover:bg-gray-50` — hover state
- `border-gray-200` — dropdown border
- `border-gray-100` — internal dividers
- `shadow-dropdown` — dropdown shadow (elevated)
- `text-gray-700` — default text
- `text-gray-500` — secondary text / icons
- `rounded-lg` — dropdown container
- `rounded-sm` — project avatar badges

## Edge Cases
1. **Zero projects:** Should not happen (onboarding creates one), but guard with empty state just in case
2. **Single project:** Dropdown still opens — shows the one project highlighted, plus "+ New project" for editors
3. **Long project names:** `truncate` class handles overflow
4. **Rapid clicks:** Toggle pattern (`setOpen(v => !v)`) handles this naturally
5. **Navigation re-render:** After `router.push`, sidebar re-renders with new `projectKey` — dropdown already closed

- The "+ New project" button is a placeholder — it will be wired in Phase 2
