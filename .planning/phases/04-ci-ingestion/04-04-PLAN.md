  <files>apps/api/src/routes/api-keys.ts, apps/api/src/routes/__tests__/api-keys.test.ts, apps/api/src/server.ts</files>
  <action>
1. Create `apps/api/src/routes/api-keys.ts` as a Fastify plugin (same pattern as other route files — export default async function with `fastify.post/get/delete`):

   **POST /api/workspaces/:workspaceId/api-keys** (requires session auth — admin/editor only):
   - Body: `{ name: string }`
   - Generate raw key: `"velo_" + crypto.randomBytes(32).toString("hex")`
   - Hash: `crypto.createHash("sha256").update(rawKey).digest("hex")`
   - Prefix: `rawKey.slice(0, 8)`
   - Insert into api_keys table via withWorkspace
   - Return 201 with `{ id, name, key: rawKey, prefix }` — raw key shown ONLY at creation

   **GET /api/workspaces/:workspaceId/api-keys** (requires session auth):
   - Return list of api keys: `{ id, name, prefix, created_at, expires_at, revoked_at }` — NEVER return key_hash
   - Order by created_at DESC

   **DELETE /api/workspaces/:workspaceId/api-keys/:keyId** (requires session auth — admin only):
   - Soft revoke: `UPDATE api_keys SET revoked_at = NOW() WHERE id = $1`
   - Return 204

2. Export a standalone **verifyApiKey** function (not inside the plugin — it's used by ingestion routes):
   ```typescript
   export async function verifyApiKey(rawKey: string, sql: postgres.Sql): Promise<{ workspaceId: string; keyId: string } | null>
   ```
   - Extract prefix (first 8 chars), compute SHA-256 hash
   - Query: `SELECT id, workspace_id FROM api_keys WHERE key_prefix = $prefix AND key_hash = $hash AND revoked_at IS NULL AND (expires_at IS NULL OR expires_at > NOW())`
   - Return { workspaceId, keyId } or null

3. Register in server.ts: `import apiKeyRoutes from "./routes/api-keys.js"` and `fastify.register(apiKeyRoutes)`

4. Implement tests in api-keys.test.ts — replace todo stubs with real tests. Mock withWorkspace and sql. Test:
   - POST returns 201 with key starting "velo_"
   - GET returns keys without hash
   - DELETE sets revoked_at
   - verifyApiKey returns null for revoked key

Note: All session-authenticated routes use the existing `request.userId` / session plugin pattern from other route files. Check runs.ts for the exact pattern.

<task type="auto">
  <name>Task 2: Ingestion routes (JUnit + Allure + payload retrieval)</name>
  <files>apps/api/src/routes/ingestion.ts, apps/api/src/routes/__tests__/ingestion.test.ts, apps/api/src/server.ts</files>
  <action>
1. Create `apps/api/src/routes/ingestion.ts` as a Fastify plugin:

   **Shared preHandler for ingestion routes** — API key auth (NOT session auth):
   - Extract `Authorization: Bearer velo_...` header
   - Call verifyApiKey() from api-keys.ts
   - If null, return 401 `{ error: "Invalid or missing API key" }`
   - If workspaceId from key does not match :workspaceId param, return 403
   - Attach keyId to request for audit

   **Increase multipart file size limit** for ingestion routes only:
   - Register @fastify/multipart with `{ limits: { fileSize: 50 * 1024 * 1024 } }` scoped to this plugin prefix (Fastify encapsulation handles this — register multipart again inside the plugin with higher limit)

   **POST /api/workspaces/:workspaceId/projects/:projectId/ingest/junit**:
   - Read multipart file via `request.file()`, buffer to memory (50MB max)
   - Generate ingestion ID (uuidv7)
   - Build R2 key via buildR2Key(workspaceId, "junit", ingestionId)
   - Upload raw bytes to R2 via uploadToR2 (BEFORE parsing — per anti-pattern guidance). If R2 is not enabled (r2Enabled() false), skip upload but continue (allows local dev without R2).
   - Parse XML via parseJUnitXml(rawBytes.toString("utf8"))
   - If parse throws, insert ci_ingestion_runs with status='parse_error', error_message, return 422 with error details
   - Build case name map: query test_cases in project, build Map<lowercaseName, id>
   - In one withWorkspace transaction:
     a. INSERT test_runs with name="CI: JUnit Import {timestamp}", source='ci', status='completed'
     b. For each NormalizedTestCase, find matching case_id from map (try fullName.toLowerCase(), then name.toLowerCase())
     c. INSERT run_items with: test_case_id (nullable), case_title from parsed name, status mapped to testStatusEnum, source='ci', comment=failureMessage if present
     d. INSERT ci_ingestion_runs with: run_id, format='junit', r2_key, status='success', total_tests=count, matched_tests=count of non-null test_case_id
   - Return 201 with `{ ingestion_id, run_id, total_tests, matched_tests, unmatched_tests }`

   **POST /api/workspaces/:workspaceId/projects/:projectId/ingest/allure**:
   - Same flow as JUnit but:
     a. Accept application/json body OR multipart file
     b. Parse via parseAllureJson
     c. R2 key uses format "allure"
     d. Run name: "CI: Allure Import {timestamp}"

   **GET /api/workspaces/:workspaceId/ingestion-runs/:ingestionId/payload**:
   - Requires session auth (not API key — this is for humans debugging)
   - Look up ci_ingestion_runs by id and workspace_id
   - If not found, return 404
   - Call getR2PresignedUrl(record.r2_key)
   - Return 200 with `{ url: presignedUrl }` (client redirects or fetches)

   **GET /api/workspaces/:workspaceId/projects/:projectId/ingestion-runs**:
   - List ci_ingestion_runs for project, ordered by created_at DESC
   - Return: id, format, status, total_tests, matched_tests, error_message, created_at, run_id

2. Register in server.ts: `import ingestionRoutes from "./routes/ingestion.js"` and `fastify.register(ingestionRoutes)`

3. Implement integration tests in ingestion.test.ts — replace todo stubs. Mock R2 (vi.mock r2.ts to no-op uploadToR2 and return fake URL from getR2PresignedUrl). Mock withWorkspace to use test DB or mock SQL. Test:
   - POST /ingest/junit with pytest fixture creates run + items
   - Auto-maps by name to existing test cases (set up test cases in mock)
   - Creates orphan items (null test_case_id) for unmatched names
   - Returns 401 without Bearer header
   - Returns 422 on malformed XML
   - POST /ingest/allure creates run from Allure JSON fixture
   - GET /ingestion-runs/:id/payload returns presigned URL

Important architectural notes:
- reply.send() MUST be called OUTSIDE withWorkspace callback (per CLAUDE.md rule)
- Use uuidv7 for all new row IDs
- testStatusEnum values are: pass, fail, blocked, skipped, untested. Map NormalizedTestCase status directly (pass->pass, fail->fail, skipped->skipped)
- The test_runs table needs a `source` column concept — use the run name prefix "CI:" to distinguish, OR add to the run name. The test_runs table does not have a source column; do NOT alter it. Just use descriptive run names.
