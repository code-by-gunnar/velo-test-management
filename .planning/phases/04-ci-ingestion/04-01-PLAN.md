   - CREATE TABLE api_keys (id UUID PK, workspace_id UUID NOT NULL FK workspaces, name VARCHAR(255) NOT NULL, key_prefix VARCHAR(10) NOT NULL, key_hash VARCHAR(64) NOT NULL, created_by UUID FK users ON DELETE SET NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), expires_at TIMESTAMPTZ, revoked_at TIMESTAMPTZ)
   - ENABLE ROW LEVEL SECURITY + FORCE + workspace_isolation policy on api_keys (same pattern as other tenant tables: `workspace_id::text = current_setting('app.workspace_id', true)`)
   - CREATE TABLE ci_ingestion_runs (id UUID PK, workspace_id UUID NOT NULL FK workspaces, project_id UUID NOT NULL FK projects, run_id UUID FK test_runs ON DELETE SET NULL, api_key_id UUID FK api_keys ON DELETE SET NULL, format VARCHAR(20) NOT NULL, r2_key TEXT NOT NULL, status VARCHAR(20) NOT NULL, total_tests INTEGER, matched_tests INTEGER, error_message TEXT, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW())
   - ENABLE ROW LEVEL SECURITY + FORCE + workspace_isolation policy on ci_ingestion_runs
   - ALTER TABLE run_items ALTER COLUMN test_case_id DROP NOT NULL
   - ALTER TABLE run_items ADD COLUMN IF NOT EXISTS source VARCHAR(10) NOT NULL DEFAULT 'manual'
   - Add index on api_keys(key_prefix, key_hash) WHERE revoked_at IS NULL

3. Add migration entry to `apps/api/drizzle/meta/_journal.json` following the existing pattern (increment idx, use tag `0004_ci_ingestion_tables`, breakpoint true).

4. Update `apps/api/src/db/schema.ts`:
   - Add apiKeys table definition matching the migration
   - Add ciIngestionRuns table definition matching the migration
   - Update runItems: change test_case_id from `.notNull()` to nullable, add `source: varchar("source", { length: 10 }).notNull().default("manual")`
   - Add `external_id: varchar("external_id", { length: 255 })` to testCases table for future external ID mapping (nullable, no constraint)

Note: Follow the exact same RLS policy pattern used in 0001_rls_policies.sql. The policy name should be `workspace_isolation` on each table.

Create realistic fixture files for each of the 5 JUnit XML variants. Each fixture should contain:
- At least 3 test cases: 1 passing, 1 failing (with failure message + body), 1 skipped
- Realistic classnames/names matching each tool's convention
- Duration (time attribute) on each testcase

**pytest-report.xml:** Root `<testsuites>` wrapping one `<testsuite>`. classname = `tests.test_login.TestLogin`. failure child with message attr + traceback text. system-out inside testcase.

**surefire-report.xml:** Root `<testsuite>` (NO testsuites wrapper). classname = `com.example.LoginTest`. Both `<failure>` and `<error>` children (one of each) to test both are mapped to fail. system-out inside testsuite.

**gradle-report.xml:** Root `<testsuite>` (NO testsuites wrapper). classname = `com.example.api.UserServiceTest`. failure child. stdout inside testsuite. Include 4 tests (1 pass, 1 fail, 1 error, 1 skipped).

**jest-junit-report.xml:** Root `<testsuites>` wrapping one `<testsuite>`. classname = describe block name (e.g., `AuthService > login`). failure with diff text.

**gotestsum-report.xml:** Root `<testsuites>` wrapping one `<testsuite>`. classname = Go package path (e.g., `github.com/org/repo/pkg/auth`). name = `TestLogin`. failure child.

**allure-result.json:** Array of 4 AllureResult objects: one passed, one failed (with statusDetails.message + trace), one broken, one skipped. Each has uuid, name, fullName, status, start, stop, labels array.

Also create a **single-test fixture** `apps/api/src/routes/__tests__/fixtures/single-test-junit.xml` with exactly ONE testcase in a testsuite (to test the isArray edge case from Pitfall 1).
