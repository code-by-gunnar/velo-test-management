<task type="auto">
  <name>Task 1: Unified auth middleware plugin</name>
  <files>apps/api/src/plugins/auth.plugin.ts</files>
  <action>
Create `apps/api/src/plugins/auth.plugin.ts` — a Fastify plugin that provides a `requireAuth` preHandler hook. The middleware tries auth sources in order:

1. **API key first:** If `Authorization: Bearer velo_*` header present, call `verifyApiKey()` from api-keys.ts. On success, set `request.userId` to the API key's `created_by`, `request.workspaceId` to the key's `workspace_id`, `request.userRole` to `"api_key"`, and `request.apiKeyId` to the key's id.

2. **Session fallback:** If no API key header (or header doesn't start with `velo_`), fall through to the existing session plugin behavior (Auth.js JWE cookie/header).

3. **Neither:** Return 401 `{ error: "Authentication required" }`.

Implementation notes:
- Export `verifyApiKey` from api-keys.ts if not already exported (it is)
- The existing session plugin already decorates request with userId/workspaceId/userRole — this plugin wraps that with API key support
- Add `request.apiKeyId` decoration (nullable string) for rate limiting and audit
- This plugin replaces the per-route `preHandler` auth check pattern. Register it as a Fastify plugin that routes can opt into via `{ preHandler: fastify.requireAuth }`.
- Do NOT remove the existing session plugin — it still handles JWE decryption. This plugin adds a layer on top.
  </action>

<task type="auto">
  <name>Task 2: Rate limiter with Valkey</name>
  <files>apps/api/src/lib/rate-limiter.ts</files>
  <action>
Create `apps/api/src/lib/rate-limiter.ts`:

- Export `createRateLimiter(valkey: Valkey, opts: { windowMs: number, max: number })` that returns a Fastify preHandler function.
- Implementation: fixed-window counter per API key in Valkey.
  - Key: `ratelimit:{apiKeyId}:{windowId}` where windowId = `Math.floor(Date.now() / windowMs)`
  - INCR the key, EXPIRE with TTL = windowMs / 1000
  - If count > max, return 429 with headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `Retry-After` (seconds until window resets)
  - If count <= max, set response headers `X-RateLimit-Limit` and `X-RateLimit-Remaining` and continue
- Only rate-limit API key requests (`request.apiKeyId` is set). Session-based requests are NOT rate-limited.
- Default config: 100 requests per 60000ms (1 minute).
  </action>
