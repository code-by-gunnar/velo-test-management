- Export `encrypt(plaintext: string): string` — returns `iv:authTag:ciphertext` as hex

  <files>apps/api/src/lib/linear-client.ts</files>
  <action>
Create `apps/api/src/lib/linear-client.ts`:

- Uses native `fetch` (Node 22 built-in) — no Linear SDK dependency needed
- Linear API base: `https://api.linear.app/graphql`

Export functions:

1. `exchangeCodeForTokens(code: string, redirectUri: string): Promise<{ access_token: string, expires_in?: number }>` — POST to `https://api.linear.app/oauth/token` with client_id, client_secret, code, redirect_uri, grant_type=authorization_code

2. `getLinearOrganization(accessToken: string): Promise<{ id: string, name: string }>` — GraphQL query `{ organization { id name } }`

3. `getLinearTeams(accessToken: string): Promise<Array<{ id: string, name: string }>>` — GraphQL query `{ teams { nodes { id name } } }`

4. `createLinearIssue(accessToken: string, params: { teamId: string, title: string, description?: string }): Promise<{ id: string, identifier: string, url: string }>` — GraphQL mutation `issueCreate`

5. `getLinearIssueStatus(accessToken: string, issueId: string): Promise<{ id: string, status: string }>` — GraphQL query for issue state name

Environment variables:
- `LINEAR_CLIENT_ID` — Linear OAuth app client ID
- `LINEAR_CLIENT_SECRET` — Linear OAuth app client secret
- `LINEAR_REDIRECT_URI` — OAuth callback URL (e.g., https://velo-test-management-production.up.railway.app/api/workspaces/linear/callback)

All functions should throw descriptive errors on API failures.

<task type="auto">
  <name>Task 3: Linear OAuth routes (connect, callback, status, disconnect)</name>
  <files>apps/api/src/routes/linear.ts, apps/api/src/server.ts</files>
  <action>
Create `apps/api/src/routes/linear.ts` as a FastifyPluginAsync:

1. `GET /api/workspaces/:workspaceId/linear/auth` — Generate Linear OAuth authorization URL and return it. Include scopes: `read`, `write`, `issues:create`. Store a CSRF state token in Valkey with TTL 10min keyed to the user's session. Return `{ url: "https://linear.app/oauth/authorize?..." }`.

2. `GET /api/workspaces/:workspaceId/linear/callback` — OAuth callback handler:
   - Validate state token against Valkey (CSRF protection)
   - Exchange code for tokens via `exchangeCodeForTokens()`
   - Fetch org info via `getLinearOrganization()`
   - Fetch teams via `getLinearTeams()` — return team list to frontend for selection
   - Store encrypted tokens + org info in linear_connections table via withWorkspace
   - If workspace already has a connection, return 409
   - Return `{ teams: [...] }` for team selection step

3. `POST /api/workspaces/:workspaceId/linear/team` — Set the default team after OAuth:
   - Update linear_connections.team_id and team_name for the workspace
   - This completes the connection flow

4. `GET /api/workspaces/:workspaceId/linear/status` — Return connection status:
   - If connected: `{ connected: true, orgName, teamName, connectedAt, connectedBy }`
   - If not connected: `{ connected: false }`

5. `DELETE /api/workspaces/:workspaceId/linear/disconnect` — Remove connection:
   - Delete row from linear_connections
   - Return `{ disconnected: true }`

Register in server.ts: `fastify.register(linearRoutes)`

All routes require auth (preHandler check for request.userId). All use withWorkspace for tenant isolation.
  </action>

<task type="auto">
  <name>Task 4: Modify defect creation to auto-file Linear issues</name>
  <files>apps/api/src/routes/defects.ts</files>
  <action>
Modify the existing `POST /api/workspaces/:workspaceId/defects` route in defects.ts:

1. After creating the local defect record in withWorkspace, check if a Linear connection exists for the workspace:
   ```sql
   SELECT access_token_enc, team_id FROM linear_connections WHERE workspace_id = $1
   ```
   (This query runs inside withWorkspace so RLS applies)

2. If Linear IS connected:
   - Decrypt the access_token via `decrypt()`
   - Call `createLinearIssue()` with the team_id, defect title, and description
   - UPDATE the defect record to set `external_id = issue.id`, `external_url = issue.url`, `external_status = 'Todo'`
   - Return the defect with external_id and external_url populated

3. If Linear is NOT connected:
   - Return the defect as-is (no error, clean silent degradation)

4. If Linear API call fails:
   - Log the error
   - Return the defect without external fields (don't fail the defect creation)
   - The defect is saved locally regardless of Linear success

Important: The Linear API call happens AFTER the withWorkspace transaction commits (defect is saved first). If Linear fails, the defect still exists. This follows the "reply.send() outside withWorkspace" rule and ensures defects are never lost due to Linear downtime.
  </action>
