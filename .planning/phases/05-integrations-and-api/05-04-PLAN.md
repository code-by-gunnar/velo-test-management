Add to the existing `linear.ts` route module:

1. `POST /api/webhooks/linear` — Linear webhook receiver (public endpoint, no auth — uses Linear signature verification):
   - Verify the webhook signature using the `linear-signature` header and the stored `webhook_signing_secret` from the linear_connections table
   - Parse the webhook payload — Linear sends `{ action, type, data, ... }`
   - Handle `type: "Issue"` + `action: "update"`:
     - Extract `data.id` (Linear issue ID) and `data.state.name` (new status)
     - Find the defect in Velo by `external_id = data.id`
     - If found, UPDATE `defects.external_status = data.state.name`
     - Publish status update to SSE channel: `run:{runId}:status` so the run view updates in real time
   - **Idempotency:** Store `webhook_delivery_id` (from Linear payload) in Valkey with TTL 24h. If already seen, return 200 immediately without processing. This prevents sync loops.
   - Handle `type: "Issue"` + `action: "remove"`: Set external_status to "Deleted"
   - Return 200 for all valid webhooks (even if defect not found — don't leak info)
   - Return 400 for invalid signature

2. During the OAuth connect flow (plan 05-03, Task 3), register the webhook with Linear:
   - After storing the connection, call Linear API to create a webhook subscription
   - URL: `{APP_URL}/api/webhooks/linear`
   - Resource types: `Issue`
   - Store the returned signing secret in `linear_connections.webhook_signing_secret`

Note: The `/api/webhooks/linear` endpoint must NOT require auth (Linear calls it). It uses signature verification instead.

  <files>

  <action>
1. Create `apps/api/src/queues/webhook.queue.ts` following the emailQueue pattern:
   ```typescript
   interface WebhookJobData {
     webhookId: string
     endpointUrl: string
     secret: string
     event: string
     payload: Record<string, unknown>
   }

   export const webhookQueue = new Queue<WebhookJobData>("webhook", {
     connection: getBullMQConnectionOptions(),
     defaultJobOptions: {
       attempts: 5,
       backoff: { type: "exponential", delay: 3000 },
       removeOnComplete: { count: 500 },
       removeOnFail: { count: 1000 },
     },
   })
   ```

2. Create `apps/api/src/queues/webhook.worker.ts`:
   - Process each job by:
     a. Compute HMAC-SHA256 signature: `hmac(secret, JSON.stringify(payload))`
     b. POST to endpointUrl with headers:
        - `Content-Type: application/json`
        - `X-Velo-Signature: sha256={hmac}`
        - `X-Velo-Event: {event}`
        - `X-Velo-Delivery: {jobId}`
     c. If response status >= 200 and < 300, mark success
     d. If response status >= 400, throw error (BullMQ will retry)
     e. Timeout: 10 seconds per attempt
   - Concurrency: 10

3. Export a helper function `fireWebhookEvent(workspaceId: string, projectId: string, event: string, payload: object)`:
   - Query active webhooks for the project where events array contains the event type
   - Also check workspace-level webhooks (project_id IS NULL) for the same event
   - Enqueue one job per matching webhook
   - This function is called from run-items and runs routes

4. Update `valkey.plugin.ts` to register webhookQueue and webhookWorker alongside emailQueue/worker.
  </action>
