<task type="auto">
  <name>Task 2: Implement POST /api/auth/oauth-signin endpoint</name>
  <files>apps/api/src/routes/auth.ts</files>
  <action>
Add the `POST /api/auth/oauth-signin` route to `apps/api/src/routes/auth.ts`, inside the existing `authRoutes` plugin function, after the `reset-password` route.

**Request body schema:**
- `provider`: string, enum `["google", "github"]`
- `providerAccountId`: string, maxLength 255
- `email`: string, format email
- `name`: string, maxLength 255, nullable (not required)

**Handler logic — single sql.begin() transaction:**

1. **Returning user check:** Query `user_oauth_accounts` JOIN `users` LEFT JOIN `workspace_members` LEFT JOIN `workspaces` WHERE `provider = ${provider}` AND `provider_account_id = ${providerAccountId}`. If row found, set `resolvedUser` and return from transaction.

2. **Email lookup:** Query `users` WHERE `email = ${email.toLowerCase()}`. Get `id, email, name, email_verified`.

3. **Unverified email guard:** If `existingUser` exists AND `email_verified = false`, set `errorCode = "unverified_email"` and return from transaction (do NOT throw — capture error code to handle after transaction).

4. **Second provider guard:** If `existingUser` exists, query `user_oauth_accounts` WHERE `user_id = existingUser.id AND provider != ${provider}`. If row found, set `errorCode = "provider_conflict"` and return.

5. **Auto-link or JIT provision:**
   - If `existingUser`: use their `id` as `userId`. Also `UPDATE users SET email_verified = true, updated_at = NOW()` (provider verified the email).
   - If no existing user: generate `userId = uuidv7()`. `INSERT INTO users (id, email, name, email_verified, password_hash) VALUES (...)` with `email_verified = true` and `password_hash = NULL`.

6. **Insert oauth account:** `INSERT INTO user_oauth_accounts (id, user_id, provider, provider_account_id) VALUES (${uuidv7()}::uuid, ${userId}::uuid, ${provider}, ${providerAccountId}) ON CONFLICT (provider, provider_account_id) DO NOTHING`.

7. **Fetch full user:** Query `users` LEFT JOIN `workspace_members` LEFT JOIN `workspaces` WHERE `u.id = ${userId}::uuid` to get the complete response shape. Set `resolvedUser`.

**After transaction (outside sql.begin):**
- If `errorCode === "unverified_email"`: `return reply.status(409).send({ error: "unverified_email", message: "An account with this email exists but hasn't been verified. Please verify your email first." })`
- If `errorCode === "provider_conflict"`: `return reply.status(409).send({ error: "provider_conflict", message: "This account is already linked to a different sign-in method." })`
- Otherwise: `return reply.send({ id: resolvedUser.id, email: resolvedUser.email, name: resolvedUser.name ?? null, workspace_id: resolvedUser.workspace_id ?? null, workspace_slug: resolvedUser.workspace_slug ?? null, role: resolvedUser.role ?? null })`

**Critical rules:**
- Do NOT call `reply.send()` inside the `sql.begin()` block (project CLAUDE.md rule).
- Use `uuidv7()` for all new row IDs (not `gen_random_uuid()`).
- Use `email.toLowerCase()` for email lookups (existing pattern).
- Error codes use snake_case strings, not HTTP-only status codes — Phase 2 Auth.js callback will map these to user-facing messages.
